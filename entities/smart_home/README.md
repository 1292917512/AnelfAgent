# 智能家居

统一聚合 Home Assistant、米家小爱音箱和小度 MCP。设备页按房间组织，连接页管理平台凭据，AI 感知页管理注入策略和设备域。

日常页面只显示实际发现的设备、房间和设备类型。已配置的平台保留连接入口；尚未接入的平台收纳在“添加设备平台”中。暂时离线的已发现设备保留状态提示，可用“隐藏不可用”筛选收起。

## 连接与控制

- Home Assistant 使用 WebSocket 订阅状态和注册表变化。先订阅再同步快照，避免连接建立期间丢失状态事件。
- 米家通过 MiNA 获取小爱音箱，后台登录与轮询，支持播放、暂停、停止、音量及播报；不代表接入全部米家设备。需要验证码时显示账号验证错误，不在服务进程中等待终端输入。
- 小度复用 MCP 管理中已配置的 `xiaodu-iot` 和/或 `xiaodu`。单个服务即可接入，另一来源断线时保留其过期快照。小度家电由平台稳定 ID 标识；缺少 ID 时使用类型、房间与名称的组合。同房间同名且平台无法精确寻址的设备禁用控制，需先在平台改名。

升级后，小度实体 ID 使用上述稳定标识。若旧规则保存过旧版小度 ID，请重新查询设备并更新引用；页面会自动使用最新清单。

控件按每台设备的实际能力显示；参数由后端动作规格统一校验。控制返回 `status: accepted` 表示平台接受命令，最终状态由后续同步确认。超时表示结果未知，应先查询状态再决定是否重试，尤其避免重复播报。断线、过期或不可用设备保留在页面并禁用控制。

SSE 提供状态更新、发现和连接事件；客户端重连后全量同步，并以周期刷新兜底。订阅队列溢出时发出重同步信号。

## AI 按需感知

默认 `smart_home_context_mode=on_demand`，工具组处于沉睡状态，仅在目录保留简短能力说明。AI 处理家居请求时调用 `activate_tool_group(group="smart_home")`，当前会话才获得设备快照和控制工具；其他未唤醒会话不注入设备状态。

快照按房间、设备域和名称稳定排序，只包含新鲜状态。各域 `inject_limit` 和全局约 2400 字符上限共同限制内容；超限提示通过 `smart_home_devices` 按房间或名称分页查询。操作前查询精确实体 ID 与该设备的 `actions`，不要从显示名猜测 ID。中文 token 用量因模型而异，字符上限不是精确 token 保证。

复用宿主的会话激活策略：默认粘性模式不会自动按轮休眠，AI 应在家居阶段结束后调用 `deactivate_tool_group(group="smart_home")`。连续家居操作中无需反复开关，以减少工具 schema 变化导致的前缀缓存失效。设备快照始终只进入 volatile 动态区。

- `smart_home_context_inject=false`：停止状态注入，仍可主动查询和控制。
- `smart_home_context_mode=always`：在实体和总开关启用时持续注入可用快照。
- 设备域禁用：同时停止该域的注入和控制。
- 面板展示“唤醒后的快照预览”，预览本身不会唤醒任何会话，也不代表某个会话正在接收它。

## 配置持久化

配置通过统一 ConfigManager 注册和保存，主文件位于 ConfigPaths 配置根目录的 `smart_home.json`，以原子写入方式持久化。主文件尚不存在时兼容读取实体目录旧 `config.json`。主文件存在后以主文件为准，不应再直接修改旧文件。

环境变量覆盖仅影响生效值，不允许从面板或 AI 回写该项。密码输入留空表示保持原值，不把脱敏占位符作为新密码提交。连接配置批量保存后合并重连通知；连接、控制和凭据轮换按平台串行处理。

小米登录令牌位于 ConfigPaths 数据目录的 `smart_home/xiaomi/`，按账号摘要隔离。小度 OAuth 先持久化轮换后的 refresh token，再一次性合并更新所有已配置的小度 MCP 凭据；保留其他环境变量和 HTTP 头。如果后续保存失败，接口报告失败，可修复存储后用新 refresh token 重试。配置和令牌均不得提交到版本库。

## 验证

后端：`uv run pytest entities/smart_home/tests entities/mcp/tests tests/unit/services/test_entity_config.py`。

前端在 `web/frontend` 运行 lint、typecheck、test 和 build；浏览器回归覆盖 `entities/smart_home/panels/e2e/smart-home.spec.mts`，包含桌面、手机、明暗主题与控制失败反馈。自动化用模拟服务覆盖协议和交互，不替代真实设备及账号联调。
