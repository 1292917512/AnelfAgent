# 设计决策

本文记录仍然对后续设计有约束力的取舍（评估过但否决的方案与重审条件），防止重新发明轮子。它不是
任务日志；如果实现发生变化，应修改对应条目的当前结论和重审条件，而不是追加记录。决策依据详见
git 历史。

## 事件溯源不是默认存储模型

不采用「模型可见消息等同于 append-only 事件日志、所有状态由纯函数投影」的全量事件溯源架构
（deepseek-harness 用它让前缀缓存稳定成为涌现性质、resume/fork/replay 免费）。AnelfAgent 同时包含
心跳、便签、多频道、记忆召回和动态上下文，把所有变化都变成事件会显著增加存储、回放和迁移成本。
需要恢复或追踪时，使用现有的回复检查点、任务交接、审计和思维会话事件（crash_recovery、PrefixGuard
观测已吸收其结论，不搬实现）。

重新评估条件：系统收敛为低动态的单会话运行时，并且 resume、fork 或 replay 成为核心产品能力。

## 不做跨轮 exec_context 去重

不把 `exec_context` 做成「值不变就不写入」的跨轮共享块。它承载轮次和经过时间等执行状态，天然随轮
变化；强行去重会增加状态同步和边界判断，却不能稳定前缀。执行状态继续由 think loop 在动态尾部按轮
组装。

## 工具目录不折叠成 Code Mode

不为了压缩工具目录而引入「生成 SDK、再由脚本分发工具调用」的 Code Mode（dsh 用它压缩模型侧
tool-catalog 体积）。IM 场景工具调用短平快，额外的代码生成和二次调度面会扩大审批、错误归因和安全
边界。需要组合控制流时，可以使用现有 codebox（`entities/codebox/`），但它只负责编排，不改变工具
目录协议。

重新评估条件：工具目录体积成为主要成本，且组合调用的收益稳定高于新增执行面的复杂度。

## 不依赖操作系统级沙箱作为主要权限模型

不把 sandbox-exec、bwrap、Landlock 或 Windows ACL 作为唯一安全边界。项目运行在用户自己的机器上，
权限判断需要理解工具、参数和会话；因此以应用层预检（shell_guard）、统一权限规则（allow/ask/deny +
参数 glob）和 Guardian 评审为主，操作系统隔离作为部署环境可以额外提供的防线。

重新评估条件：运行不再是单用户自托管，或需要对不可信租户提供强隔离执行环境。

## 错误使用语义原因，不建立全局数字码

工具错误统一使用 `core/tool_errors` 的语义原因（ErrorCause 字符串枚举）、可重试标记和操作提示。
不同模块可以为协议适配保留局部数字码，但不建立跨模块的第二套数字错误契约；调用方应按原因和
结构化字段处理，不解析展示文本。

## 保持写入前读取约束

文件编辑继续要求已有文件先经过读取或建立可信基线，不能因为缓存缺失就自动放宽写入门槛（已有测试
`test_existing_file_requires_read` 锁定严格门）。这样可以防止模型在未看到当前内容时覆盖文件；
需要追加内容时使用专门的 append 语义，并保留现有冲突检查。

## EventBus 不保留拦截语义

处理器返回 ``False`` 中断后续处理器的 ``emit_with_result``（曾与 ``emit`` 并存）从未有过模块外
调用方：审查/否决类需求由权限规则与 Guardian 承担，before_reply 等事件均走普通 emit。它顺序等待
与 ``emit`` 的并发语义不一致，once 清理也作用在迭代前的旧列表上，属未经使用验证的推测性 API，
已裁剪。需要拦截时按当时的真实场景重新设计，不复活旧实现。

重新评估条件：出现必须由事件处理器阻断主流程的需求（如 before_reply 审查门要否决回复本身）。

## 其他已核验关闭项

对照 pi / ZCode / Codex 等成熟栈逐项验证后关闭，不再重复评估：

- 截断工具调用投毒防护（本项目两级续写更强）、edit_file 四级模糊匹配（平局偏优）、tiktoken+usage
  锚（领先 chars/3.5 估算）、MCP 刷新单飞（等效）、中断规范化与崩溃账本（已覆盖）
- durationMs 持久化（与思考链内存驻留设计冲突）、per-model 分账（记入统一路由验收标准）、CIMD
  （需公网 URL）——否决
- 挂起待需求：MCP 按根覆盖（多项目根需求）、headless 粘贴式登录（anelf serve 条目）
- DI 容器与装饰器注册表方案否决（解析图无消费场景；RuntimePorts 无法跨 entities/agent 分层定型），
  晚绑定端口是最终形态（见[架构分册](architecture-reference.md)）
- 声纹嵌入级均值减除/白化（会移动余弦阈值标定，需重训不适用动态小库）、PLDA（需标注数据）、
  活体检测（本地单用户场景无需求）——见[声纹分册](audio-voiceprint.md)

## 主思维并发模型：单航班 Driver，否决两类替代（2026-10-19）

背景事故：同一用户消息触发元决策同时产出 REPLY 与 PLAN/TOOL_ACTION，决策执行层
`asyncio.gather` 并行即时决策、deferred 决策裸 `create_task` 后台化，导致同一指令被
两条思维链重复执行（重复思考、重复工具操作、reply_active 守卫互撞）。

终态：`agent/mind/driver.py` 单航班调度器——消息周期、心跳 tick、手动任务、元决策
与决策执行共用唯一常驻 worker 串行推进；受理只登记并唤醒（latch 合并、忙时锁存、
关停释放认领）；心跳决策在决策边界向新到的用户消息让路。并行只保留给显式隔离执行体
（子代理/Delegation、LLM 钩子、工作流 ask、Minecraft 自主轮次与思维循环内只读工具并发）。

已否决的替代与重审条件：

- **给 `Mind.reflect()` 加全局锁**：覆盖不了不经 reflect 的元决策调用，且前台子代理、
  同步钩子会在锁上自等待。重审条件：执行面出现 reflect 之外的不可收口并发入口。
- **每 scope / 每决策独立并行思维**（旧实现）：多频道多用户是同一个 Mind 的感知与注意力，
  不是多个互不知情的平行大脑；并行决策导致重复执行与守卫互撞。重审条件：出现需要真正
  独立人格或独立上下文的多 Agent 形态。
- **心跳决策后台并行化**（2026-08 引入，本事故根因之一）：原意是受理不阻塞消息，正确
  形态是「受理非阻塞 + 执行串行」，已由 Driver 承接，不再恢复。
