# 设计决策

本文记录仍然对后续设计有约束力的取舍。它不是任务日志；如果实现发生变化，应修改对应条目的当前结论和重审条件，而不是追加轮次记录。

## 事件溯源不是默认存储模型

不采用“模型可见消息等同于 append-only 事件日志、所有状态由纯函数投影”的全量事件溯源架构。AnelfAgent 同时包含心跳、便签、多频道、记忆召回和动态上下文；把所有变化都变成事件会显著增加存储、回放和迁移成本。需要恢复或追踪时，使用现有的回复检查点、任务交接、审计和思维会话事件。

重新评估条件：系统收敛为低动态的单会话运行时，并且 resume、fork 或 replay 成为核心产品能力。

## 不做跨轮 exec_context 去重

不把 `exec_context` 做成“值不变就不写入”的跨轮共享块。它承载轮次和经过时间等执行状态，天然随轮变化；强行去重会增加状态同步和边界判断，却不能稳定前缀。执行状态继续由 think loop 在动态尾部按轮组装。

## 工具目录不折叠成 Code Mode

不为了压缩工具目录而引入“生成 SDK、再由脚本分发工具调用”的 Code Mode。当前工具调用以短任务为主，额外的代码生成和二次调度面会扩大审批、错误归因和安全边界。需要组合控制流时，可以使用现有 codebox，但它只负责编排，不改变工具目录协议。

重新评估条件：工具目录体积成为主要成本，且组合调用的收益稳定高于新增执行面的复杂度。

## 不依赖操作系统级沙箱作为主要权限模型

不把 sandbox-exec、bwrap、Landlock 或 Windows ACL 作为唯一安全边界。项目运行在用户自己的机器上，权限判断需要理解工具、参数和会话；因此以应用层预检、统一权限规则和 Guardian 评审为主，操作系统隔离作为部署环境可以额外提供的防线。

重新评估条件：运行不再是单用户自托管，或需要对不可信租户提供强隔离执行环境。

## 错误使用语义原因，不建立全局数字码

工具错误统一使用 `core.tool_errors` 的语义原因、可重试标记和操作提示。不同模块可以为协议适配保留局部数字码，但不建立跨模块的第二套数字错误契约；调用方应按原因和结构化字段处理，不解析展示文本。

## 保持写入前读取约束

文件编辑继续要求已有文件先经过读取或建立可信基线，不能因为缓存缺失就自动放宽写入门槛。这样可以防止模型在未看到当前内容时覆盖文件；需要追加内容时使用专门的 append 语义，并保留现有冲突检查。
