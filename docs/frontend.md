# 前端结构

React/TypeScript 前端的页面组织、模块插件体系与工作区对话联动的现状说明。修改
`web/frontend/src/` 时按需阅读；模块 UI 扩展点契约见 [ui-contributions.md](ui-contributions.md)。

## 页面结构

页面采用壳组件 + 子面板目录拆分模式，通用 TabBar 切换：

```text
pages/
├── Chat.tsx             # 对话工作台（首页，三栏：文件树/对话流/功能 Dock）→ chat/
├── Retrieval.tsx        # 检索（/retrieval：能力×提供者矩阵 + 抓取设置）→ retrieval/
├── Dashboard.tsx        # 总览 → dashboard/
├── Memory.tsx           # 记忆 → memory/
├── Config.tsx           # 配置中心 → config/（左侧模块树 + 检索 + 基础/高级分区 + 详情抽屉；
│                        #   数据驱动自 /config/meta，⌘K 与 /config?key= 深链定位）
├── Tasks.tsx            # 任务管理（独立页面）
├── Heartbeat.tsx        # 心跳 → heartbeat/（状态 + 配置与调度）
├── Models.tsx           # 模型 → models/
├── Channels.tsx         # 频道 → channels/
├── Thinking.tsx         # 思维链路
└── ...

components/common/TabBar.tsx  # 统一标签栏（溢出时左右翻动按钮、滚轮/触屏横向滚动、选中项自动可见）
lib/types.ts / api.ts         # API 接口类型（api 实例已导出供插件复用）
lib/core-routes.ts            # 核心路由注册表（Sidebar 据此识别插件导航项）
lib/channel-plugins.ts        # 频道前端插件注册表
lib/plugin-i18n.ts            # 插件 i18n 自注册
lib/utils.ts                  # cn() 类名合并工具
i18n/locales/{zh,en}/         # 核心 namespace（zh/en key 一一对应；插件文案不进核心 locale）
```

核心页面在 `lib/core-routes.ts` 声明懒加载路由、导航分组与展示信息；导航、命令入口和路由宿主
复用这份注册表，页面文案由对应 i18n namespace 提供。模块页面通过 `app.routes` 贡献点注册。
应用先绘制启动状态，扩展清单就绪后才创建正式 Router，避免漏掉模块路由。

Cognee 的“模型与配置”按抽取模型、召回查询、同步构图、存储保护分区；常用参数直接展示，
高级参数折叠。通用字段、约束与分区来自 `CogneeConfig` 的字段元数据，由配置 API 下发，
前端不另维护字段名单。抽取模型请求超时复用 `chat.extra_args.timeout`，留空恢复模型继承，
状态接口另报当前运行时采用的超时；保存值与待批次结束后生效的运行值须分开展示。
数据目录只读展示，位置调整统一走数据管理。

## 模块前端插件体系（热插拔）

频道/实体的前端与后端收敛到同一模块目录，核心框架只做通用加载，删除模块目录即整体拔出
（UI/API/文案/路由零残留）：

- **频道前端**：`channels/<id>/frontend/` 自持清单、组件、API、类型和翻译。`module-links.mjs`
  生成懒加载清单，构建以 `@channels` 别名直接消费源码。`index.ts` 声明 `login` / `panel` /
  `hiddenInChannelList`；整页内容经 `contributions.ts` 的 `app.routes` 插槽注册。核心频道管理面由
  注册表驱动，禁止按具体频道 ID 硬编码
- **实体面板**：`entities/<name>/panel.tsx`（+ `panels/` 子目录）经 `module-links.mjs` **代码生成**
  接入——扫描生成 `src/generated/entity-panels.ts`（懒加载表）与 `entity-panel-locales.ts`（locale
  eager 表），面板源码经 `@entities` 别名以真实路径被 tsc/vite/eslint 直接消费（无软链、无提交
  残留，生成文件 gitignored，prebuild/dev watcher 自动重写）；面板专属 i18n 放
  `panels/locales/{zh,en}.json`，由 `lib/entity-plugin-locales.ts` eager 注册（locale 静态打入主
  chunk）；locale 保留键 `_registry` 以显式映射声明全局词汇（`groups` / `configSections`）——
  实体组名翻译一律自持于模块目录，核心 tools.json/config.json 不写实体条目；无面板的实体也可只建
  `panels/locales/`（locale-only 实体同样被代码生成收录）；面板专属 API/类型放 `panels/api.ts` /
  `panels/types.ts`（不污染核心 lib）
- **跨页面扩展**：核心仅提供类型化插槽与渲染宿主，禁止直接导入具体实体/频道组件、API 或协议类型。
  模块在 `contributions.ts` 声明工作区工具、总览卡片、整页路由、数据页签、重启控件、音频区域和
  消息渲染器，详见 [ui-contributions.md](ui-contributions.md)
- 插件 API 复用核心 axios 实例（`import { api, apiErrorMessage } from "@/lib/api"`）

## 共享动效与弹层生命周期

表单使用 `Input`、`Textarea`、`Select`、`Switch`；`form-control` 统一边框、字体、禁用态和
窄屏触控高度。`Select.className` 控制外层布局，必要的控件尺寸覆盖通过 `controlClassName`；
保留原生 `select` 的值、事件、键盘和表单语义。支持 `appearance: base-select` 的浏览器采用
主题化选项层和短过渡，不支持时回退原生菜单；多选和列表模式不启用弹出式样式。
弹窗内打开原生选项层时，Esc 先交给选择器，避免 Radix 的关闭处理取消原生行为或一起关闭编辑器。

浮动预览、菜单和模型选择器统一使用 `PopoverContent`，复用 Radix 的定位与焦点机制；
公共组件负责 Portal、视口避让、滚动边界、边框阴影及进退动画，页面只保留内容与必要的尺寸约束。
批量破坏性操作使用 `ConfirmDialog`，提交期间禁用重复操作；失败保留确认界面供查看错误和重试。

页面入口只做短淡入，不对实时刷新和列表逐项重播动画；交互反馈采用统一的时长与缓动令牌。
卡片、按钮明确声明颜色、边框、阴影与透明度过渡，进度条仅平滑宽度，避免 `transition-all`
意外动画表单展开、内容尺寸与布局变化。所有动效遵守系统 reduced-motion。

Modal / Drawer 通过 `open` 驱动 Radix Presence；Popover Content 使用 `floating-surface`
复用方向感知的进入和退出动画，不叠加独立淡入类。关闭态不可接收指针操作。
表单的取消、确认和辅助操作放入 `Modal.footer`，按取消在前、主操作在后的顺序排列；
公共 `dialog-actions` 统一按钮高度、间距和窄屏伸展，内容区滚动时保留操作区。
`Modal` 在退出期间保留最后一次打开时的展示内容，避免清空选中项后标题、正文或按钮闪变；
嵌套弹层同时关闭时，子层不会把焦点恢复到正在退出的父层。应用内确认使用 `ConfirmDialog`，
不使用浏览器原生 `window.confirm`；提交期间通过 `loading` 阻止重复提交和意外关闭。
按需挂载的编辑/详情会话可使用 `useDialogSession`：校验或未保存确认通过后调用 `close`，
将 `surfaceProps` 传入主弹层，`onAfterClose` 在退出、焦点恢复后通知宿主卸载并清理草稿。
该钩子仅用于一次挂载对应一次打开的会话；长期挂载的弹层仍由宿主直接控制 `open`。

## 工作区对话联动

| 机制 | 位置 | 说明 |
|------|------|------|
| @提及 | `chat/mention/` + ChatInput | 输入框 `@` 触发文件模糊搜索（200ms 防抖 + 陈旧结果丢弃）；选中写 `[name](./path)` markdown 链接（路径信号，不预读内容，AI 用 read_file 自取）；`./` 前缀防渲染器误当协议；气泡侧 MentionMarkdown 还原为可点击文件 chip |
| 粘贴占位符 | ChatInput.handlePaste | 大段文本（≥400 字符）转 `[Pasted Content N chars]` 占位符 + 全文作为 txt 附件 |
| 工作区上下文注入 | `services/workspace_context.py` + workbench-store + FileEditor | 发送时把「当前文件/选中代码（行列+内容）/打开标签页」渲染为固定前缀块注入；格式与回放清洗同一约定（REQUEST_DELIMITER 分隔符，历史渲染 rsplit 取用户原文）；预算：选区 40k/标签 100/合计 20k 字符。注入放消息动态区不触碰前缀缓存；失败降级不阻塞发送 |
| 改动集面板 | `stores/changes-store.ts` + `render/ChangesCard.tsx` | EVENT_FILE_DIFF 按 turn 累积为「本轮改动 N 个文件」可折叠卡片沉淀进消息历史；点击单文件展开 diff、「open」跳编辑器 |
| 编辑器联动刷新 | FileEditor 订阅 fileVersions | AI 改文件后已打开标签自动刷新磁盘内容（有未保存草稿时不覆盖） |
| 审批语义化 | ApprovalPreview + ApprovalDialog | 审批弹窗按工具类型分发渲染：edit/write 出极简 diff（红绿行）、shell 出命令全文+cwd、delete/create 出受影响路径列表；识别不出走通用参数兜底 |

## 工作区展示层

Web 对话首屏与向前翻页每批 40 条。补同步使用已归并的服务端 `after_id` 高水位，按 ID 升序
逐批追平；某批失败保留已成功的游标，重试不跳过中间消息。取消会话加载同时中止 HTTP 请求，
迟到响应不能恢复已释放的历史。实时文本只在历史确认匹配后归并，未落库消息、附件和未确认提交保留。
正常跟随最新内容时最多保留 120 条已落库消息；上翻阅读期间暂停裁剪，向前分页保持原消息锚点。
「返回最新消息」收缩至最近 40 条并补同步；离开会话同样释放展开历史。
切换会话时只保留最近三个会话的已落库正文缓存，正在提交或等待回复的会话暂缓淘汰；释放正文不清除草稿和待发送附件。
后台核对不插入首屏加载占位，自动跟随直接定位最新内容，避免连续平滑滚动积压。

文件刷新信号保留最近 512 个路径，并保护已打开的编辑器；修订单调递增，路径淘汰后再次出现
仍能触发更新。文件树的徽章与闪烁共用最多 200 条变更记录，不另存无限增长的路径索引。
已加载目录每 600ms 最多刷新 8 个，其余继续排队，持续事件不会延后已有刷新窗口；
重命名同时排队来源和目标目录，关闭面板释放队列与订阅。

聊天附件在上传期间使用本地临时预览，上传成功后改用服务端返回的媒体 URL 并释放临时地址；
消息 Markdown 不持有 blob URL。历史附件保留工作区文件引用，图片放大预览复用统一弹窗的焦点与关闭管理。

工作区实时过程经 `core.activity` 事件投影到 `services.workspace_activity` 的有界内存记录。
SSE 与 WebSocket 在出队时由 `services.activity_stream.ActivityStreamEncoder` 按连接编码：
首次发送完整轮次，后续 `activity_delta` 只传变化字段、变化步骤及正文追加；步骤列表变化时附完整 ID 顺序。
增量带 `epoch` 与 `base_revision`，前端按连接维护解码基线，与 HTTP 快照的展示状态分离。
缺失基线或修订不匹配时沿用有界退避重连，并通过完整基线与活动快照恢复；重复或旧修订
不会回退终态或重复追加正文。订阅队列仍合并完整状态，
增量基于实际出队帧生成，慢连接跳过中间进度也不会丢失工具回执。连接关闭即释放有界基线。
HTTP 健康核对传入同进程的快照修订，仅返回变化轮次及存续 ID；未变化轮次不重复复制和下载。
存续 ID 同步服务端淘汰，迟到 HTTP 响应不能覆盖更新的实时帧；进程变化回退完整快照。
连接解码按每个修订连续进行；展示层在一帧内合并同轮进度，终态立即提交，旧连接的待提交帧失效。
模型调用按调用 ID 配对并保留用途，压缩摘要不投影为普通回复正文。
上下文压缩、记忆沉淀、文件恢复与 Cognee 维护复用 `core.activity.activity_step` 发布阶段事实；
维护使用独立活动归属。活动事件只供观测，不改模型消息、token 或缓存前缀。
顶栏显示所选执行树的触发来源、会话发送者及主题；未筛选时以最新轮次为焦点。子代理按委派标识合并续跑，包含排队和嵌套委派；计划与子代理详情按需打开，复用已有实时数据。模块可通过 `activity.summary.actions` 扩展入口，不向模型上下文写入展示摘要。
轮内收到的消息、实体通知及跨会话感知增量在实际并入上下文时展示，跨会话快照按会话消息水位去重。
正文开关关闭时不生成通知；实际发送只在工具或投递卡片展示，出站历史同步不重复生成通知。
工具恢复判断作为单独的过程卡片，详情沿用悬停预览、点击弹窗与手机底部详情页。
展示副本脱敏并限制长度，不改模型输入；卡片区分来源、收发角色与进入轮次，进入上下文不等于已处理。
当前思考正文直接展开；工具行仅呈现类型摘要、目标标签、状态和耗时，标题支持鼠标悬停预览、点击详情和键盘操作，手机使用底部详情页。
技能摘要区分候选、显式注入与成功读取，最多展示三个名称；弹窗查看全部匹配事实并跳转技能库，不将读取等同于步骤完成。
技能页的近期参与按技能聚合并按轮数降序展示，分别统计推荐、读取与显式调用；编辑按需读取正文，不将运行记录持久化。
同一轮模型调用的思考归入模型用量行，调用中展开；未手动选择时随调用结束收起，手动展开或收起保持到本条记录卸载。
正文与详情共用 Markdown 渲染器，渲染组件身份保持稳定。代码块先显示完整纯文本，复用
`useInViewport` 在进入视野附近且输出稳定后执行语法高亮；屏外和折叠区域内的代码不提前
生成高亮节点，展开后自动补齐，复制始终使用完整原文。
纯文本与高亮代码保持相同行高；长消息从首帧限制高度，折叠态展开按钮叠放在渐变区，避免测量后增加消息高度、挤离最新消息。
文件引用用图标和语义色区分技能与记忆，保留原有文件根和打开目标。
工具正文、终端输出和大段 Markdown 仅在打开详情时挂载，关闭后卸载；沿用统一弹层、动效和 reduced-motion 规则。
当前过程按步骤开始时间交织展示，各段标明会话和父任务；工具完成或补回回执不会改变已有步骤的位置。支持按会话树筛选和打开完整执行详情。
历史归档按父子关系分组，持续运行的后台任务不会把后续无关会话合并为一轮。当前页保持最新会话及仍在执行的任务，其余按需翻阅。

实时过程左侧阶段刻度从现有执行顺序派生，连续工具合并刻度；悬停或键盘聚焦显示短预览，
点击定位并暂停自动跟随。阶段保持会话归属，后台钩子不切断前台步骤。
右侧上方提供「回忆过程」「判断记录」浮窗，按当前执行页的会话归属展示上下文准备、
记忆深探和技能准备及其判断结果。下方分为任务、子代理和异步任务，只列运行项，完成后自动移除；
未筛选会话时展示全局正在运行的工作，筛选后只展示对应执行树。子代理按委派标识合并续跑，
钩子投影与关联执行不重复计数，历史详情仍由原执行记录承载。钩子与 Jev 详情不占主流程正文。
宽栏显示名称和数量，窄栏保留图标及数量；长模型名截断并可查看全称，宽表格和代码只在自身内部滚动，
不扩大实时过程的横向滚动范围。同步上下文准备在主时间流显示简短阶段，判断与完整证据仍按需查看。
通用后台任务通过同一活动快照显示描述、状态和实际耗时，完整结果仅在详情弹窗中挂载。
主回复结束不代表它发起的后台任务结束；迟到终态按发起轮次更新，子代理及钩子沿用各自展示以避免重复。
复用同一有界活动快照，不新建订阅；窗口关闭不挂载详情，
窗口内各步骤默认收起。首轮准备结果与实际进入模型上下文的记录分别展示，技能候选不视为已执行。
Jev 判断默认显示一行任务、结论、耗时与异常标记；点击后才挂载概率、依据、模型用量和慢响应诊断。
自动跟随以时间流末尾为锚点，布局变化和流式更新在动画帧内合并处理；上翻阅读暂停，向下滚回底部恢复，显式暂停由按钮恢复。
内层代码或结果仍可消费的滚动不影响外层跟随；迟到的自动滚动事件不能恢复阅读暂停。
计时刷新只更新相应标题，未变化的步骤与阶段复用展示引用。工具摘要和结果通过 `activity.tool` 挂载模块内视图，核心只提供通用组件与回退。
Web 与思维链共用 SSE 连接生命周期实现，终止连接退避重建；业务事件和现有心跳都更新收帧时间。
前台持续收帧停滞时关闭旧连接并退避恢复，后台暂停积极判定；回到前台时保留仍新鲜的连接，
已失效或长时间无收帧的连接立即重建并补拉快照。网络恢复与手动同步复用同一重建入口。
连接错误统一走有界退避，不并用浏览器重试；快照健康检查独立于重连等待，实时流不可用时仍可补齐状态。
连接状态、快照补齐和智能体忙闲分别呈现；HTTP 服务可用不代表实时流健康。手动重新同步复用同一入口。
重连补拉当前和等待活动的会话；普通回复仅更新送达消息，不结束活动展示。历史中出现 assistant 消息也
不等于执行完成。等待收束只使用服务端消息身份与关联活动的覆盖证据，缺少证据时保留提交状态，
发送受理后立即核对历史与活动快照；前台静默期间由原有会话核对任务每十秒补齐，持续收到过程时推迟核对。
没有完成证据不能因等待超时撤去等待状态；后台暂停核对，回到前台复用连接恢复入口。
请求超时保留本地消息 ID，历史对账后更新送达状态，不自动重发。
上下文用量按 Web 会话分桶，未观察到用量的会话不复用其他会话数据。
工作区复用 `status` 和 `thinking` 查询读取现有思维阶段及待处理队列，覆盖尚未生成活动轮次的等待与元决策。
这些全局事实不推断某条消息已读，也不合成活动记录；心跳正常不代表活动帧已同步。
活动恢复由单个实时连接的前台健康检查驱动，展示组件只呈现阶段与队列。静默活动按十秒窗口核对；
完整快照按三十秒窗口兜底（健康检查粒度十秒），不依赖主思维是否忙碌，避免其他频道持续输出掩盖子代理终态或独立维护。
会话核对与全局检查复用 `activity-store.reconcile`，共享在途请求和最近检查时间；同步新鲜度使用本地收取时间。
历史的并发调用等待同一次归并及必要的尾随刷新；未变的消息、步骤和列表保留引用。
折叠与子代理快照仅在首次加载和恢复时补齐，不随静默历史核对重复请求；空的子代理运行快照清除旧运行卡片，
但不会编造完成结果，且不覆盖请求期间收到的新事件。排队中的委派保留在当前执行页及子代理列表。
连接栏只声明实时传输状态；没有活动记录不代表智能体空闲。
活动通知的总数与展示摘要数分别呈现；观测副本截断不改变实际模型输入，也不能用于推断逐条已读。

过程阅读状态独立于分栏挂载：`activity-view-store` 只保存当前进程的页、筛选、展开 ID、跟随模式与条目锚点，
不复制活动正文。分栏切换或响应式重建恢复锚点；活动淘汰后清理失效引用，进程 epoch 变化不沿用旧锚点。
分栏增减由面板库的动态注册处理，不通过布局组合的 `key` 重建整个面板组；仅显式重置布局时重建。
阅读暂停时容器尺寸变化恢复原步骤锚点，布局导致的滚动不能覆盖用户的阅读位置。
自动恢复跟随需要向下阅读意图，布局调整或迟到滚动事件不能恢复暂停。
前台正文按动画帧合并，后台降低展示提交频率，终态及停止反馈及时提交；连接关闭清理待提交任务。
正文和详情共同遵守流式高亮策略，页面隐藏时暂停经过时间计时，恢复可见立即校准。
只有元数据变化时保留步骤列表引用；阅读位置在动画帧内合并保存，通过有序步骤二分定位锚点，
避免每次滚动逐条测量长列表。跟随末尾时无需读取步骤布局。
计划和委派在主时间流展示进度与当前目标，步骤、风险和结果复用二级详情按需挂载。
弹窗宿主保持挂载，通过 `open` 驱动 Radix Presence，退出动画结束后才卸载正文；
不能用 `open && <Modal>` 绕过退出生命周期。详情懒加载时先显示弹窗与加载反馈。
工作区浮窗与详情共用进入/退出节奏，只动画透明度与位移，并遵守 reduced-motion。
快照请求由 activity-store 合并，所有调用方等待同一请求；同修订记录保留引用，旧进程的迟到失败不覆盖新进程状态。
完整过程帧在订阅者发送队列中按进程和轮次覆盖旧快照，完成帧无需等待同轮积压版本；消息回执、文本增量和其他轮次保持独立顺序。
前端按步骤 ID 复用未变化的内容引用，运行计时和其他步骤的流式更新不驱动已完成结果重绘。页面回到前台时补拉快照，替换或关闭连接后的迟到事件不再更新界面。
执行详情优先订阅实时数据，仅断连且仍有活动步骤时补拉；过期记录停止轮询，错误与过期分别提示并支持手动刷新。

## AI 提问与页面在场信号

`UiCommandHost` 在各页面承接 `ui_ask`，选项选择与自由输入统一通过底部提交；
失败保留草稿，跳过和超时均不代表同意。宿主保留正文到退场动画及焦点恢复结束，再展示下一问题。
问题携带截止时间，`ask_closed` 同步多页面终态，过期问题不可再提交。

`ui-state-reporting` 每 15 秒按页面实例上报连接、可见性、焦点和距最近操作的秒数；
可见性和连接变化立即上报，关闭使用 keepalive 请求，序号防止迟到请求覆盖新状态。
后端租约 45 秒失效，优先选择可交互页面，后台页面不会覆盖另一页面的活跃状态。
`ui_get_state` 区分 `active / background / idle / offline`；5 分钟无操作标记 idle。
`ui_ask` 仅在存在近期操作的前台页面时发起，等待期间所有页面离线则提前返回未回答。
这些信号仅表示页面可能可交互，不能证明用户在场、已阅读或已授权。

## 前端开发约定

- 页面超过 300 行拆为子面板目录、统一用 TabBar、i18n 覆盖所有文本、`Record<string, unknown>`
  替换为 `lib/types.ts` 接口
- 分层保持 stores ← pages 单向；Tailwind 构建同时扫描实体面板和频道前端源码，模块内声明的完整
  工具类名直接生效，不要用字符串拼接生成类名
- 前端架构测试机械校验「核心不导入具体模块组件」的边界

## 管理列表与请求反馈

人物和说话人管理由列表组件、领域查询与操作 Hook、弹窗组合分别负责；表单草稿由已有身份表单持有。
共用筛选 Hook 只管理输入、防抖提交和分页，不接管网络调度。领域 queryOptions 保持查询键、参数、
取消信号和刷新策略一致，复用 React Query 的缓存与请求协调。翻页保留旧内容并显示刷新状态；
关键词提交时同步回到第一页。身份合并候选独立筛选、分页，避免将当前列表页误当作全部候选。

普通写请求沿用客户端全局错误反馈。已经在调用处展示错误的请求通过 Axios 配置
`errorFeedback: "local"` 声明反馈归属，此配置不进入请求负载；鉴权失效仍统一处理。
请求取消不展示失败，后台查询失败保留已有数据并提供刷新入口。

实时表现验证复用浏览器事件流替身驱动真实前端解码与渲染，覆盖连接恢复、布局重建、连续更新与详情阅读。
性能场景记录收帧到展示的样本并附到测试产物；浏览器视口测试不替代真实模型、网络或物理移动设备验收。
